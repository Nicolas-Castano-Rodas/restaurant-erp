# Auditoría de operaciones

/dashboard/audit requiere team.manage y rol Propietario; consulta de toda la organización con filtro por sucursal y tipo de acción y páginas de 50. Eventos nuevos escritos explícitamente dentro de las transacciones de servicios de pedidos, cocina, caja, inventario manual, recetas, compras, proveedores, clientes, domiciliarios y equipo. La recepción y consumo de ingredientes conservan el detalle por ingrediente en StockMovement; la bitácora registra la operación principal. No se escriben eventos por reintentos idempotentes que devuelven una operación anterior, ni por operaciones fallidas. El usuario, rol y sucursal corresponden al contexto de ejecución. El nombre y rol del actor se guardan al momento; el nombre de sucursal mostrado es actual. Detalles seleccionados, no una copia completa de datos anteriores y posteriores. No se incluyen contraseñas, tokens, contactos ni motivos libres. No se implementa edición o eliminación desde la interfaz. Las claves foráneas restringen eliminación de actores y sucursales con eventos. No es almacenamiento inmutable frente a un administrador de PostgreSQL. No hay reconstrucción histórica, auditoría de autenticación, cambios de contraseña, exportaciones, ni cambios directos en BD. Catálogo y mesas se integrarán en una ampliación. Política de retención y exportación de auditoría pendientes. Aplicar npm run db:deploy antes de iniciar. Pruebas de integración comprueban aislamiento, ausencia de datos secretos, rollback y recepción idempotente.
