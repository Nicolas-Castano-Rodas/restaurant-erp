# Administración y cuenta

/dashboard/team requiere team.manage y el rol reservado Propietario, comprobados también en cada transacción. Administración de toda la organización, no solo la sucursal seleccionada. El propietario existente se conserva, no se cambia ni se desactiva desde la interfaz. Los roles operativos permiten seis permisos existentes, sin delegar team.manage. Se crean cuentas con correo globalmente único y contraseña inicial de 12 caracteres mínimo y 256 bytes máximo; no se vinculan cuentas preexistentes de otras organizaciones. Se asigna rol y una o varias sucursales activas. Desactivar una membresía no desactiva el usuario global. Modificar acceso revoca sesiones de esa membresía; cambios de permisos se verifican en cada solicitud. No se eliminan usuarios ni roles. Las sucursales nuevas asignan acceso al propietario que las crea; no se permite desactivar sucursales desde esta versión.

Cualquier usuario autenticado puede cambiar su contraseña en /dashboard/account con la contraseña actual. Se usa scrypt y se revocan todas sus sesiones al cambiarla. La contraseña inicial debe comunicarse de forma segura; no se fuerza el cambio todavía. Invitaciones, recuperación por correo, MFA, límites adicionales para operaciones de contraseña, auditoría de administración y gestión de organización pendientes. No se necesita migración. Pruebas de integración de roles, acceso entre organizaciones, protección del propietario, cambio de sucursal y contraseña.
