## Demo alojada: certificado de PostgreSQL
La base dedicada restaurant-erp de Supabase tiene 15 migraciones Prisma aplicadas y 31 tablas con RLS; se revocaron los permisos de anon, authenticated y service_role. Se verificó un propietario y se cargó un catálogo ficticio con 12 productos y recetas, 10 mesas, 15 ingredientes y saldos iniciales, sin pedidos ni pagos. No usar la base para operaciones reales. La integración usa el rol administrativo para esta demo inicial; antes de uso comercial separar un rol de ejecución de privilegios mínimos.

Para Vercel, guardar DATABASE_URL con sslmode=verify-full y DATABASE_CA_CERT con el contenido PEM completo del certificado descargado del proveedor. La aplicación utiliza un objeto TLS con rejectUnauthorized=true y combina la CA explícita con las autoridades predeterminadas de Node.js para no perder la confianza del pooler; no configura NODE_TLS_REJECT_UNAUTHORIZED=0. Las migraciones Prisma CLI se ejecutan por separado, desde la terminal autorizada, con NODE_EXTRA_CA_CERTS apuntando al certificado local si es necesario. Mantener la Data API desactivada. Verificar /api/ready y el inicio de sesión antes de compartir el enlace. No publicar credenciales. No se ha verificado todavía el despliegue en Vercel.
